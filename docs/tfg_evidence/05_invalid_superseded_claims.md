# 05 — Superseded and Invalid Claims

Purpose: prevent a future session (or the thesis text itself) from resurrecting a mistake that was already found and corrected during this project. Each entry states the old claim, why it's wrong/superseded, and what replaced it.

> **Rule for this table, learned the hard way (rows 6 and 7).** A "Replaced by" cell must **point at the authoritative file**, never restate a value or a scheme from it. Rows 6 and 7 both previously restated the very things they were meant to retire — row 6 asserted "5 repetitions, ~30 s per run" as the formal protocol after the manifest had set both to `null`, and row 7 named the superseded `BASE/B1/C1/C2/D1/D2` set as the current one. A restated value goes stale silently and then reads as settled. A pointer cannot.
>
> Authoritative files: `experiment/manifest.yaml` for parameters and rationale, `experiment/run_matrix.csv` for cells. Prose documents in this directory, including this one, are indexes.
